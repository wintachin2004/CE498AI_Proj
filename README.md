# ระบบทำนายความเสี่ยงอุบัติเหตุทางถนน (Accident Risk Prediction)

โปรเจกต์นี้วิเคราะห์ข้อมูลอุบัติเหตุทางถนนของไทยปี **2019–2026** (รวม ~189,000 เหตุการณ์)
เพื่อทำนายว่า **จังหวัดไหน ในช่วงเวลาไหน (ชั่วโมง/วัน/ฤดูกาล)** มีความเสี่ยงต่อการเกิด
อุบัติเหตุสูง พร้อมแดชบอร์ดเว็บแอปสำหรับดูสถิติและทดลองทำนาย

## โครงสร้างโปรเจกต์

แยกเป็นโฟลเดอร์ `backend/` กับ `frontend/` ชัดเจน เพื่อให้แต่ละคนในทีมทำงานคนละส่วนได้
โดยไม่ชนไฟล์กัน — คนทำโมเดล/ข้อมูลทำงานใน `backend/`, คนทำ UI ทำงานใน `frontend/`

```
accident-prediction-project/
├── backend/                       # ทีม Data/Backend ทำงานตรงนี้
│   ├── data/
│   │   ├── raw/                   # ไฟล์ CSV ต้นฉบับรายปี (2019-2026)
│   │   └── processed/             # ข้อมูลที่ทำความสะอาดแล้ว + ตารางความเสี่ยง
│   ├── models/
│   │   ├── random_forest.pkl
│   │   ├── gradient_boosting_model.pkl
│   │   ├── catboost_model.cbm     # (สร้างเฉพาะถ้าติดตั้ง catboost ไว้)
│   │   └── metadata.pkl           # ตัวเข้ารหัสฟีเจอร์ + รายการตัวเลือกสำหรับฟอร์ม
│   ├── src/
│   │   ├── preprocessing.py       # รวม/ทำความสะอาดข้อมูล + สร้างฟีเจอร์เวลา
│   │   ├── train.py               # สร้างตารางความเสี่ยง + เทรนโมเดล
│   │   ├── predict.py             # โหลดโมเดล และทำนายระดับความเสี่ยง
│   │   └── compare_models.py      # เทรน CatBoost + เทียบกับ baseline/RF/GB
│   ├── app.py                     # Flask backend: เสิร์ฟหน้าเว็บ + API
│   └── requirements.txt
│
├── frontend/                      # ทีม UI/Frontend ทำงานตรงนี้
│   ├── templates/
│   │   └── index.html             # โครงหน้าเว็บ
│   └── static/
│       ├── style.css              # ดีไซน์แดชบอร์ด
│       └── app.js                 # เรียก API + วาดกราฟ/แผนที่/ฟอร์มทำนาย
│
├── notebooks/
│   ├── 01_data_cleaning.ipynb
│   └── 02_model_training.ipynb
└── README.md
```

**หมายเหตุสำหรับทีม:** `app.py` (ใน `backend/`) เป็นตัวรวมสองฝั่งเข้าด้วยกันตอนรัน — มันเสิร์ฟไฟล์ HTML/CSS/JS
จาก `frontend/` และเปิด API endpoints (`/api/...`) ให้ฝั่ง frontend เรียกใช้ ดังนั้นเวลาแก้ไข
UI แก้ที่ `frontend/` ได้เลยโดยไม่ต้องแตะโค้ด Python เพราะ `app.js` คุยกับ backend
ผ่าน REST API เท่านั้น (ดูรายการ endpoint ทั้งหมดได้ในไฟล์ `backend/app.py`)

## แนวคิดของโมเดล

ข้อมูลดิบเป็น "เหตุการณ์ที่เกิดขึ้นแล้ว" (event-level) ไม่มีตัวอย่างเชิงลบ (ไม่เกิดเหตุ)
จึงใช้วิธี:

1. รวมข้อมูล (aggregate) เป็นตาราง **จังหวัด × ช่วงเวลา (hour_bin) × วันในสัปดาห์ × ฤดูกาล**
2. คำนวณ **คะแนนความเสี่ยง** จากความถี่ของอุบัติเหตุต่อปี + น้ำหนักความรุนแรง (ผู้เสียชีวิต/บาดเจ็บ)
3. แบ่งคะแนนเป็น 4 ระดับด้วย quantile: **ต่ำ / ปานกลาง / สูง / สูงมาก**
4. เทรนโมเดล classification (Random Forest, Gradient Boosting) ให้ทำนายระดับความเสี่ยง
   จากฟีเจอร์ จังหวัด/ช่วงเวลา/วัน/ฤดูกาล — ทำให้ทำนายชุดค่าที่ไม่เคยเจอตรง ๆ ในอดีตได้ด้วย

ผลการประเมิน (test set 20%): Gradient Boosting ทำได้ accuracy ~58% และแยกกลุ่ม
"ต่ำ" กับ "สูงมาก" (สองขั้วที่สำคัญที่สุดในการเตือนภัย) ได้ดีที่สุด (recall 69% และ 80% ตามลำดับ)

> **ข้อควรระวัง**: นี่คือการประเมินความเสี่ยง**เชิงสถิติ**จากรูปแบบในอดีต ไม่ใช่การพยากรณ์
> ว่าจะเกิดอุบัติเหตุจริงหรือไม่ ควรใช้เป็นข้อมูลประกอบ ไม่ใช่คำตัดสินสุดท้าย

## วิธีติดตั้งและรัน

คำสั่งทั้งหมดรันจากข้างใน **`backend/`** (เพราะ `app.py`, `src/`, `data/`, `models/`
อยู่ในนั้นด้วยกัน — ส่วน `frontend/` ถูกเสิร์ฟผ่าน `app.py` ให้อัตโนมัติ ไม่ต้องรันแยก)

```bash
cd backend

# 1. ติดตั้งไลบรารี
pip install -r requirements.txt

# 2. (ถ้ายังไม่มี data/processed/) รันทำความสะอาดข้อมูล
python src/preprocessing.py

# 3. (ถ้ายังไม่มี models/) เทรนโมเดล
python src/train.py

# 4. รันเว็บแอป
python app.py
```

จากนั้นเปิดเบราว์เซอร์ไปที่ **http://localhost:5000**

## แดชบอร์ดมีอะไรบ้าง

- **เช็คความเสี่ยง** — เลือกจังหวัด/ช่วงเวลา/วัน/ฤดูกาล แล้วดูระดับความเสี่ยงพร้อมความน่าจะเป็นแต่ละระดับ
- **กราฟสถิติ** — จำนวนอุบัติเหตุตามชั่วโมง, วันในสัปดาห์, เดือน, สภาพอากาศ
- **แผนที่ความหนาแน่น (Heatmap)** วัน × ชั่วโมง
- **10 จังหวัดเสี่ยงสูงสุด** และ **สาเหตุที่พบบ่อยที่สุด**
- **แนวโน้มรายปี** จำนวนอุบัติเหตุเทียบกับผู้เสียชีวิต
- **แผนที่จุดเกิดเหตุจริง** (กรองตามจังหวัดได้)

## เทรน CatBoost แล้วเทียบกับโมเดลอื่น

ในเครื่องที่ใช้สร้างโปรเจกต์นี้ไม่มีอินเทอร์เน็ต จึงยังไม่ได้ติดตั้ง/เทรน CatBoost
ให้คุณรันเองในเครื่องที่มีอินเทอร์เน็ตดังนี้ (จากข้างใน `backend/` เหมือนเดิม):

```bash
cd backend
pip install catboost
python src/compare_models.py
```

สคริปต์นี้จะ:
1. สร้าง train/test split **ชุดเดียวกันเป๊ะ** กับที่ใช้ใน `train.py` (random_state=42, stratify)
   เพื่อให้เทียบผลระหว่างโมเดลได้ตรงกัน ไม่มีความได้เปรียบจากการสุ่มข้อมูลต่างกัน
2. ประเมิน **2 baseline ง่าย ๆ**:
   - `most_frequent` — ทายกลุ่มที่พบบ่อยที่สุดเสมอ (ตัวชี้วัดขั้นต่ำที่โมเดลต้องทำได้ดีกว่า)
   - `stratified` — ทายแบบสุ่มถ่วงน้ำหนักตามสัดส่วนจริงของแต่ละกลุ่ม
3. โหลด Random Forest และ Gradient Boosting ที่เทรนไว้แล้ว (หรือเทรนใหม่ถ้ายังไม่มีไฟล์โมเดล)
4. เทรน CatBoost ด้วยชุดฟีเจอร์เดียวกัน แล้วบันทึกเป็น `models/catboost_model.cbm`
5. พิมพ์ตารางเปรียบเทียบ accuracy / F1 (macro) / F1 รายระดับความเสี่ยง เรียงจากดีที่สุด
   และบันทึกไว้ที่ `data/processed/model_comparison.csv`

ผลจากรันในเครื่องนี้ (ไม่มี CatBoost) เป็นตัวอย่างว่าตารางหน้าตาประมาณนี้:

| model | accuracy | f1_macro |
|---|---|---|
| Gradient Boosting | 0.583 | 0.573 |
| Random Forest | 0.499 | 0.489 |
| Baseline: stratified random | 0.249 | 0.249 |
| Baseline: most_frequent | 0.250 | 0.100 |

พอมี CatBoost แล้วมันจะโผล่มาในตารางนี้ด้วย ถ้า F1 macro สูงกว่า Gradient Boosting
ก็อัปเดต `app.py` ให้โหลด `catboost_model.cbm` แทน (ใช้ `CatBoostClassifier().load_model(...)`
แทน `joblib.load(...)` เพราะ CatBoost มีฟอร์แมตของตัวเอง)

## การอัปเดตข้อมูล

เมื่อมีไฟล์ข้อมูลปีใหม่ ให้วางไฟล์ `accidentYYYY.csv` ไว้ใน `backend/data/raw/` แล้วรัน
`python src/preprocessing.py` และ `python src/train.py` ใหม่ (จากข้างใน `backend/`)
สคริปต์ preprocessing รองรับคอลัมน์ที่ชื่อไม่ตรงกันในแต่ละปีอยู่แล้ว
(ดูตัวแปร `COLUMN_CANDIDATES` ใน `src/preprocessing.py`) ถ้าปีใหม่มีชื่อคอลัมน์ที่ต่างไปอีก
ให้เพิ่มชื่อนั้นในลิสต์ที่เกี่ยวข้อง

ไม่ตรงกับตอนเทรนโมเดล (.pkl) — ให้รัน `python src/train.py` ใหม่ในเครื่องนั้นเพื่อเทรน
โมเดลด้วยเวอร์ชันที่ติดตั้งอยู่จริง (ใช้เวลาไม่กี่นาที เพราะข้อมูลที่ทำความสะอาดแล้วมีอยู่แล้ว
ไม่ต้องรัน `preprocessing.py` ใหม่)
